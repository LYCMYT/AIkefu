# AIkefu Executable Eval V2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Convert the 40 retrieval queries and 72 product cases into versioned, executable, honestly reported evaluation suites without replacing the existing 36 fixed and 10 AUTO baselines.

**Architecture:** Preserve both CSVs as immutable sources, compile them through strict aliases and per-case overrides into canonical JSON, then run two separate executors: `KnowledgeService.search` for retrieval and the existing production reply path/reliability harness for product cases. Every source ID produces exactly one result with an explicit PASS, FAIL, BLOCKED_UNSUPPORTED, BLOCKED_ENVIRONMENT, or NOT_RUN status, and generated evidence remains outside Git.

**Tech Stack:** TypeScript 5, Node.js, NestJS, Jest/ts-jest, Prisma/PostgreSQL/pgvector, Redis/BullMQ, MinIO, pnpm.

**Spec:** `docs/superpowers/specs/2026-09-02-eval-v2-design.md`

## Global Constraints

- Keep `seed/eval-cases.json` (36 cases) and `seed/auto-eval-cases.json` (10 cases) unchanged.
- Preserve all 40 retrieval and 72 product source IDs exactly once.
- Never count FAIL, BLOCKED_UNSUPPORTED, BLOCKED_ENVIRONMENT, or NOT_RUN as PASS.
- Never infer aliases with fuzzy matching; every alias and per-ID override is explicit and validated against Seed Catalog keys.
- Every execution uses an isolated Workspace and full workspaceId/tenantId/shopId scope, plus productId/buyerId/conversationId where applicable.
- Static facts require frozen Knowledge Evidence; inventory, price, order, and logistics require scoped dynamic Task results.
- No API keys, tokens, cookies, passwords, connection strings, database rows, or MinIO objects in reports or Git.
- Use tests-first for every production behavior and retain the original failure output in the task log.
- Do not stage `.codex-tmp/`, `deliverables/`, or generated `artifacts/eval-v2/` files.

- [ ] **Step 3: Implement strict compilation**

Implement exact mappings and validation:

```ts
export function compileEvalV2(input: CompileEvalV2Input): EvalV2CanonicalBundle {
  const retrieval = input.source.retrieval.map((row, index) => compileRetrievalRow(row, index + 2, input));
  const product = input.source.product.map((row, index) => compileProductRow(row, index + 2, input));
  assertExactIds(retrieval, /^Q(?:0[1-9]|[1-3][0-9]|40)$/);
  assertExactCount(product, 72, 'PRODUCT_CASE_COUNT');
  return canonicalBundle(input, retrieval, product);
}
```

Validation must reject fuzzy aliases, unknown task targets, invalid Seed keys, scope/product mismatch, `Positive=NO` with nonzero rank, `Positive=YES` with zero rank, Q37 without conflict override, unknown setup actions, ambiguous slash/arrow messages without an override, and any source ID absent from the output.

Atomic writes use two temporary sibling files, fsync/close, then rename only after both serializations succeed. A cleanup branch removes temporary files on failure while leaving previous canonical files unchanged.
